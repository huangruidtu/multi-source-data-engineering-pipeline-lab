# Module 06 — Data flow and runtime

For current `order_id=1001`, external `CORE_ORDERS` is selected through a dbt source. Staging casts/names fields; intermediate enrichment joins rate data and sets a missing-DKK-rate flag rather than fabricating conversion. `fct_orders` joins customer/date surrogate keys and merges the current row; its post-hook removes physically absent current Silver orders. A payment links through `fct_orders`; if it is orphaned, the left join retains evidence and the relationship test warns. `fct_payments` rebuild makes a removed/relinked payment correct next run. Snowflake execution, dbt compile/run/test and cost behavior are **RUNTIME DEFERRED — not runtime validated**.
